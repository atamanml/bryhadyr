# Протокол агентів · v2 (українська версія)

Єдине джерело правди для всіх агентів власника (Claude Code у хмарі, на сервері, на ноутбуці; Hermes у Telegram; чати claude.ai).
Змінити підхід для всіх = змінити цей файл і запушити: плагін, закомічені шаблони і SOUL-блок Hermes розносять його самі.
Англійська версія: `PROTOCOL.md` (тримати синхронно).

## 1. Де що живе

| Що | Де | Як туди пишемо |
|----|----|----------------|
| Задачі | OpenTodo, MCP-сервер `tasks`  | інструменти `search_tasks`, `create_tasks`, `update_tasks`, `complete_tasks`, `add_comment` |
| Документація і нотатки | Obsidian-vault, у репо інфра-репо `obsidian/` | файл у репо → push у `main` → деплой кладе у vault |
| Код і плани проєкту | репозиторій проєкту (`docs/`, `README`) | як завжди, PR/коміт |

Проєкти в OpenTodo: **Власник**, **Сім'я** (по одному на людину), **Дім**, **Агенти** (секції = репозиторії: `infra`, `app-a`, `app-b`, `інше`).
Мітки: `agent` (створив агент), `blocked`, `waiting` (чекає людину), `quick` (≤ 15 хв), `idea`, `done-by-agent` (закрив агент).
Папка нотаток проєкту в Obsidian: `obsidian/10 - Проекты/<Назва проєкту>/` (назва як у OpenTodo: `Інфраструктура`, `Застосунок A`, …; нова папка = новий проєкт, створюй без питань).

## 2. Що таке «велика задача»

Велика = окреме повідомлення власника з завданням, яке змінює понад один файл або триває понад ~30 хвилин, або будь-що, що потім треба
буде згадати (рішення, деплой, нова інтеграція, розслідування). Усе інше (поміняти колір кнопки, виправити одрук) — мала: трекер не чіпаємо,
хіба власник сам каже «запиши».

## 3. Ритм сесії (Claude Code і claude.ai)

1. **Старт.** Подивись відкриті задачі свого проєкту: `search_tasks`/`list_tasks` по секції репозиторію. Якщо завдання власника вже є в
   трекері — працюй з нею (`update_tasks` → status doing), не плодь дублікат.
2. **Початок великої задачі.** Нема в трекері — створи одну задачу в «Агенти» (секція репо, мітка `agent`, статус doing):
   назва = дієслово + що, ≤ 120 символів; у нотатках одним реченням, що просив власник.
3. **Кінець великої задачі.** Обов'язково, перед фінальною відповіддю:
   - **Obsidian-нотатка** `obsidian/10 - Проекты/<Проєкт>/<YYYY-MM-DD> <Назва>.md` за шаблоном у розділі 5 (summary, що зроблено,
     перевірки, рішення, що лишилось). Коміт у `main` інфра-репо (з іншого репо — через `gh api`/GitHub MCP
     `create_or_update_file`, див. скіл; obsidian-зміни йдуть у `main` без PR).
   - **Задача в OpenTodo**: `complete_tasks` + `add_comment` з коротким підсумком у форматі розділу 4. Мітка `done-by-agent`.
   - **Follow-up**: усе, що лишилось людині, заблоковане або відкладене — окремі задачі (`agent`, без дедлайну, ≤ 5 за сесію),
     з посиланням на нотатку.
4. **Мала задача.** Нічого в трекер; якщо з неї виросло «треба потім» — одна задача-follow-up.
5. **Раз на сесію, не частіше.** Не оновлюй трекер після кожного кроку; один підсумок наприкінці великої задачі.

PM-агент розкладає задачі агентів по пріоритетах і дедлайнах; агенти дедлайнів не ставлять.

## 4. Формат підсумку в задачі (коментар `add_comment`, 6–10 рядків)

```
Зроблено: <1–2 речення що саме>
Перевірено: <тести/лінти/ручна перевірка, з результатом: «24 тести зелені», «curl /healthz → 200»>
Не перевірено: <чого не можна було перевірити звідси і чому>
Рішення: <1–3 ключові рішення з причиною>
Далі: <follow-up задачі за назвами або «нема»>
Нотатка: obsidian/10 - Проекты/<Проєкт>/<файл>.md · <посилання на PR/коміт/сесію>
```

## 5. Шаблон Obsidian-нотатки

```markdown
---
project: <Проєкт>
date: <YYYY-MM-DD>
task: <id задачі в OpenTodo або «—»>
agent: <claude-code-cloud | claude-code-server | claude-code-laptop | hermes | claude.ai>
status: done | partial | blocked
tags: [agent, <репо>]
---
# <Назва задачі>

**Суть:** одне речення, навіщо це робилось.

## Що зроблено
- …

## Перевірки
- <що запускав> → <результат>

## Рішення і чому
- …

## Що лишилось / ризики
- …

Посилання: <PR, коміт, сесія, документ у репо>
```

Мова нотаток і задач — українська; код, коміти, назви файлів — як у проєкті. Секретів у нотатках і задачах не буває ніколи.

## 6. Hermes (Telegram) і claude.ai

- Hermes: блок «Протокол: персональний PM» у SOUL.md (`hermes/install.sh`) посилається на цей файл, а не копіює його, бо SOUL їде з кожним повідомленням у Telegram; нотатки пише у `~/obsidian/10 - Проекты/<Проєкт>/` напряму.
- claude.ai (веб/застосунок): інструкції проєкту в claude.ai = розділи 1–4 цього файлу; конектор `tasks` увімкнений. Обидва оновлює власник
  вручну після зміни протоколу (рідко).

## 7. Чат-оркестратор і витрати

Власник ставить мету, чат доводить її до результату: спершу розбирається сам, потім діє, питає лише те, що належить вирішувати власнику.
Ціна ≈ виклики × середній контекст × ціна моделі.

- **Одна задача = одна сесія.** Окрема робота (інший репо, свій PR) іде в нову сесію з брифом; дрібне лишається в цьому чаті.
  Звіт сесії — це заява: результат і дифф перевіряє оркестратор.
- **Передача файлом, не компакт.** Контекст понад 250k → handoff 1–2 КБ: готово, далі, файли `шлях:рядки`, що пробували і чому не вийшло, відкриті питання.
- **Субагенти не економлять:** 2–3 на задачу, по одному, бриф ≤ 2 КБ (задача, файли, критерій готовності). 180k контексту або 80 викликів → здає роботу.
- **Кеш:** не міняти `CLAUDE.md`, плагіни, MCP і модель посеред задачі. Команди понад 3 хв — у фоні, а не в петлі очікування.
- **Читати діапазонами, правити патчем,** вивід тестів згортати до підсумку й падінь, звіти короткі.
- **Моделі:** середня — реалізація й рутина; старша — ревʼю диффа, числова логіка; найсильніша — 1–2 архітектурні розвилки; найменша — пошук.
- **Перевірка не урізається:** «готово» лише після запуску. Економія, яка дає понад 20 % переробок, фіктивна.
